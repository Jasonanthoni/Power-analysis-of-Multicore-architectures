# Goal 2: Verification of gem5 → McPAT Power Analysis Pipeline

## Objective

To understand and verify how gem5 simulation outputs are converted into power estimates using McPAT without modifying any files.

---

## Pipeline

gem5 Simulation
        │
        ▼
stats.txt
config.ini
config.json
        │
        ▼
gen_mcpat_xml.py
        │
        ▼
mcpat_input.xml
        │
        ▼
McPAT
        │
        ▼
mcpat_output.txt

---

## Files Used

### Input Files

stats.txt
- Contains runtime statistics generated by gem5.
- Includes instruction counts, cache statistics, memory accesses, execution cycles, IPC, etc.

config.ini
- Contains architectural configuration.
- CPU model
- Cache hierarchy
- Memory configuration
- Ruby configuration

config.json
- JSON representation of the architecture.

---

### Conversion Script

gen_mcpat_xml.py

Purpose:
- Reads gem5 output files.
- Generates mcpat_input.xml.

---

### McPAT Input

mcpat_input.xml

Purpose:
- Hardware description understood by McPAT.
- Contains processor configuration and runtime statistics.

---

### McPAT Output

mcpat_output.txt

Contains

- Area
- Peak Power
- Runtime Dynamic
- Leakage Power
- Cache Power
- Core Power
- Memory Controller Power

---

## Verification

Successfully executed

./mcpat -infile ../power_analysis/mcpat_input.xml

McPAT generated the expected power report successfully.

---

## Observation

The gem5 baseline configuration corresponds to

- X86
- 16 cores
- Ruby
- MESI Two-Level

However, the current McPAT report summarizes

- Total Cores: 2

This observation will be investigated before using the previous team's results as the research baseline.

Possible reasons:

- XML generated from another experiment
- Parser limitation
- McPAT template configuration
- Different stats/config files

The complete gem5 → McPAT pipeline has been successfully verified.
